## Overview

Enterprise-grade IAM, API Security, and AI Security company website. Static single-page application deployed on **integrauth.com** via GitHub Pages.

**Core Services**: AI & Agent Security (agent authentication, non-human identities, MCP security & secure MCP libraries, FGA/ReBAC, AI integrations), Enterprise IAM, API Security Gateway, Cloud Integration (AWS/Azure/GCP), Enterprise SSO

**Brand line**: "Identity & Security for All — Humans, Machines, RPA bots & AI Agents" (two-line hero tagline; updated 2026-07-13, was "...for Humans, Machines & AI Agents" from the AI-first rebrand, 2026-07)

**Tech Stack**: HTML5, CSS3, JavaScript ES6+, jQuery 3.7.1, Bootstrap 5.3.3, Font Awesome 6.4.0

**Deployment**: migrating from GitHub Pages to **Cloudflare Workers** (`wrangler.toml` + `src/worker.ts`). The Worker serves the repo root as static assets (`[assets] directory = "."`, `run_worker_first = ["/api/academy/*", "/auth/*"]`, `not_found_handling = "404-page"`, `html_handling = "auto-trailing-slash"`) and runs the Academy API at `/api/academy/*` plus the OIDC Relying Party at `/auth/*`. **`run_worker_first` must list every prefix `src/worker.ts` dispatches on** — a prefix handled in the Worker but missing there is answered by the asset server first and 404s on a route that looks correctly implemented. The front end still has no build step (hand-written HTML/CSS/JS + the existing minify commands); only the Worker is TypeScript, bundled by Wrangler. `workers_dev = true` and **no `routes`/`custom_domain` block on purpose** — integrauth.com still points at GitHub Pages until the owner cuts DNS over by hand; don't add one until that cutover is actually happening. Local dev: `npm run worker:dev` (never bare `wrangler dev` — the assets dir IS the repo root, so wrangler's own `.wrangler/` state retriggers its watcher and reload-loops; see the gotcha comment in wrangler.toml). Security headers: `_headers` covers static asset responses, `src/lib/server/security.ts` covers API responses — keep the two in sync.

**Analytics** (2026-07-18): Cloudflare Web Analytics beacon (`static.cloudflareinsights.com/beacon.min.js`, zone-wide token `fa2d8aba…36b2` — the same token sunnahfast already used) appended before `</body>` on all 11 pages (support/privacy/cancellation have NO closing `</body>` tag — minifier stripped it — so the snippet sits at EOF there). Same token rolled out to all product/tool/demo repos. Pageviews/referrers/Core Web Vitals only — NO custom events by deliberate choice (Akhil, 2026-07-18; academy progress/cert/click stats would need a first-party Worker, parked). View in CF dashboard → Analytics & Logs → Web Analytics, filter by hostname. Academy is hash-routed, so lesson navigation = one pageview.

**URL style**: ALL internal links are extensionless (`/academy`, `/privacy`, `/#contact`, `/` for home) — GitHub Pages resolves `/academy` → `academy.html`, and so does the Worker's asset server (`html_handling = "auto-trailing-slash"`, which additionally 307s `/academy.html` → `/academy`). Never link `*.html` directly; canonicals and sitemap.xml are extensionless too.

Structure:

- **Hub** (`#acadHub`): 12 `.acad-track-card`s with static lesson TOCs (SEO/noscript-friendly); each card carries a `.acad-track-num` "Track N" pill (order: basics 0, foundations 1, authn 2, tokens 3, authz 4, proto 5, ai 6, ops 7, atk 8, ciam 9, cloud 10, arch 11 — reader label mirrors it as "Track N · Name"; the same order must hold in TRACK_LABELS numbering, hub card DOM order, lesson-section DOM order, and the index promo mini-card grid). The hub also injects (via initAcademy, no-JS-safe): a **lesson search** box (`.acad-hub-search`, filters all lessons by title+lead), **persona learning paths** (`.acad-paths`: 4 role cards Developer/Architect/Security-analyst/PM, each an ordered cross-track playlist from PERSONA_PATHS in functions.js — unknown ids auto-skip), and **glossary tooltips** (`.acad-term` spans hover/focus → `.acad-tip` popover, definitions harvested from f11-glossary dt/dd); below the cards sits the **Flow Explorer** panel (`#acadFlows`, a hub-level `.acad-lab` `data-lab="lab-flows"`): a 12-flow picker rendering animated SVG sequence diagrams via the flow-player engine — `AcadLabs.defineFlow(id, {title,tag,intro,outro,actors,steps})` registry + `h.flowPlayer(refOrDef)` helper in academy-labs.js (step-by-step reveal, plain-English narration + optional HTTP snippet, Back/Next/Auto-play, ax-*/--acad-* theming, `.acad-seq-*` CSS block in styles.css); flows: oidc-code, webauthn, refresh-rotation, dpop, backchannel-logout, saml-sp, saml-idp, client-creds, device, token-exchange, ciba, scim-provision — lesson labs may embed any via h.flowPlayer. Below that sits **Challenge mode** (`#acadChallenge`, see the Interactive labs bullet below), then a **Final Exam** panel (`#acadExam`, `data-lab="lab-exam"`): 50 questions stratified-drawn from `ACAD_EXAM_POOL` (96 Qs, 8 per track — round-2 additions 2026-07-20 are harder/scenario-based; draw guarantees GUAR=4 per track then fills randomly to N=50) in academy-labs.js, 80% to pass. **The exam + certificate are the ONLY sign-in-gated part of the Academy** (2026-07-28) — logged-out visitors get a "🔐 Sign in to take the final exam" panel instead of the quiz, while lessons, labs, Flow Explorer and Challenge mode stay fully public and account-free. On a pass the flow is server-backed end to end: `POST /api/academy/exam/attempts` records the attempt → `GET/PUT /api/academy/profile` collects or confirms the learner's first+last name (the server rejects empty/whitespace names and **locks** the name the first time a certificate is issued, so the old "Identity Learner" placeholder default is gone) → `POST /api/academy/certificates/issue` mints and stores the certificate. The browser only *renders* what the server returns: the canvas PNG is drawn from the server's holder name / score / issued-at / serial, and the JWT artifact is fetched separately from `GET /api/academy/certificates/:serial/jwt`. Certificates are durable, so the panel lists a learner's previous certificates and can re-download any of them; a learner who passed while logged out is offered a one-time "save this local pass to my account" claim step. **The old client-side `certId()` scheme is GONE** (`IA-YYYYMMDD-<score>-<8 hex>` / `integrauth-academy-cert-v1` salt / canonical-name SHA-256) — never reintroduce a browser-computed certificate ID. **verify.html** (`/verify`, in sitemap) is now a plain server lookup: it calls the public, cookie-free `GET /api/academy/certificates/verify/:serial` and renders holder name + score + issue date, or "no match" (Bootstrap form modeled on support.html, uses solid `btn-primary` — the site's `.btn-outline-primary` masked-border style renders with artifacts, avoid it). The serial is a human-transcribable, unguessable `IA-XXXX-XXXX-XXXX` code minted server-side (it must stay unguessable — `/certificates/verify/:serial` is public, so a guessable serial would be an enumeration oracle for holder names). The signed JWT is a secondary, offline-checkable artifact only: ES256 with a `kid` header, public half served from `GET /api/academy/.well-known/jwks.json`, and deliberately NO email claim (learners forward the JWT to third parties). Certificate internals were still being iterated on 2026-07-28 — read `src/lib/server/certs.ts` + `src/lib/server/api.ts` before relying on exact claim/format details here. `.acad-exam-*`/`.acad-cert-canvas` CSS in styles.css. Grow ACAD_EXAM_POOL with each new track; `#acadResetAll` in `.acad-hub-foot` clears all LOCAL progress behind a confirm() — it does **not** delete server-side progress, which re-merges on the next sync for a signed-in learner (only account deletion removes that)
- **Reader** (`#acadReader`): one-lesson-at-a-time via `initAcademy()` in functions.js — hash routing (`#lesson-id`), chip nav per track, prev/next pager, localStorage progress (`acad_pos`/`acad_pos_at`/`acad_read`/`acad_quiz`, debounced-synced to the server when signed in — see the accounts section below), quiz reveal buttons, glossary live filter (input injected by JS). **Read-marking is gated by lesson type** (since v5.39): lessons WITH a `.acad-lab` only mark read once the lab is interacted with (any pointerdown/keydown inside the lab — delegated in functions.js, `academy-labs.js` untouched; a JS-injected `.acad-lab-gate` line above the lab says "Try the hands-on lab below…" → "✓ Lesson marked read.", reusing `.acad-quiz-progress` styling incl. `.done`); labs are open-ended sims with no uniform end state, so interaction — not completion — is the signal. Lessons WITHOUT a lab (★ intros, `*-summary`, f11-glossary) mark read on open as before, and `*-quiz` lessons keep their all-5-reveals gate. Hub-level labs (`#acadFlows`/`#acadChallenge`/`#acadExam`) sit outside `.acad-lesson` and never mark anything. Reset buttons are track-scoped: `.acad-reset-track` (top toolbar `#acadReset` + `.acad-reader-foot` bottom bar, which also has an "All tracks" `data-goto="__hub__"` button — backing out to the hub clears `acad_pos` but deliberately WRITES a fresh `acad_pos_at` tombstone rather than clearing it: the merge adopts the server's position when `!localAt || serverAt > localAt`, and `!localAt` is the first clause, so clearing the timestamp makes adoption unconditional and the next visit dumps the learner back into the lesson they just left) clears only the active track's read marks + quiz reveals via `resetTrack()`, then returns to the hub. `*-quiz` recap lessons don't mark read on open: per-question reveals are tracked in `acad_quiz` with a JS-injected `.acad-quiz-progress` line + per-question ✓, and the lesson counts as read only after all 5 answers are revealed. ### Accounts, shared SSO & the Academy API (2026-07-28)

The Academy was anonymous until this change; it now has **optional accounts**, and the account is **shared with the sister product at lab.integrauth.com** (`integrauth/lab` repo) — same user record, same physical D1 database (`lab-db`, bound as `DB` in wrangler.toml).

**SIGN-IN IS OIDC, NOT A SHARED COOKIE (redesigned 2026-07-30 — read this before touching auth).** The first design shared ONE session cookie between both apps (`__Secure-ia_session` with `Domain=.integrauth.com`). That was rejected on security grounds and reverted before it ever deployed. Cookie identity is `(name, domain, path)` and the `__Secure-` prefix only demands TLS — it does **not** restrict who may *set* the cookie (`__Host-` does, which is exactly why `__Host-` forbids `Domain`). So any of the ~30 sibling `*.integrauth.com` hosts (27 free-tool subdomains, the product apps, the 3 demos) could have replied `Set-Cookie: __Secure-ia_session=<attacker token>; Domain=.integrauth.com` and overwritten a visitor's session: session fixation (victim's progress, real name and certificates land in the attacker's account) plus an unclearable forced logout, and the token was transmitted to all ~30 hosts on every request. **Never reintroduce a cross-subdomain session cookie.** Instead: each app holds its own `__Host-` cookie and integrauth.com is an **OIDC Relying Party** against the Lab's OpenID Provider (Authorization Code + PKCE S256).

Two corollaries that are easy to get wrong, both found by re-audit on 2026-07-30:

- **The sibling subdomains are still SAME-SITE with us**, because "site" means the registrable domain. `__Host-` stops a sibling *writing* our cookie; it does nothing to stop a sibling *spending* it, and `SameSite=Lax` withholds nothing between same-site origins. So the Origin allowlist + `application/json` requirement in `guardStateChanging` (api.ts) is **load-bearing CSRF defence, not belt-and-braces** — an earlier comment claimed Lax had made it redundant, which would have justified deleting it. Don't.
- **Cookie-name selection keys on the HOSTNAME, not the URL scheme.** `sessionCookieName` returns the unprefixed dev name only for `localhost`/`127.0.0.1`. Keying it on `url.protocol !== 'https:'` (the original) correctly refused the dev name over HTTPS but happily *served* it to a plaintext `http://integrauth.com` request — and a cookie with no `__Host-` prefix is one any sibling can set with `Domain=`, reopening the exact fixation hole above. Nothing in either repo forces HTTPS at the zone level and our HSTS omits `preload`, so first-ever contact was genuinely exposed.

- **Ownership split**: the Lab owns the `users` and `sessions` tables *and* the entire account lifecycle (email OTP signup/login, its own logout, revoke-all, TOTP step-up, account erase) — plus it is the OpenID Provider. This repo owns its OWN sessions in `website_sessions` (Lab migration 0052) behind cookie `__Host-ia_web_session`, minted only at the end of an OIDC callback. It READS the Lab-owned `users` table (permitted, read-only: `validateSession` joins it for `status` — so a disabled or erased account stops working here on the next request — and for the email the navbar shows). It never touches the Lab-owned `sessions` table at all any more. Never run migrations from this repo against `lab-db`, and never write a Lab-owned table from here.
- **RP surface** (`src/lib/server/auth.ts` + `oidc-rp.ts`, routed via `run_worker_first`): `GET /auth/start` (PKCE verifier + `state` + `nonce` in a short-lived `__Host-ia_oidc_tx` cookie, then redirect to the Lab's `/authorize`), `GET /auth/callback` (exchange at `POST /oidc/token` with `client_secret_basic`, verify the ID token against the Lab's JWKS incl. `nonce`, mint our session), `GET /auth/session` (who-am-I; also the only route that re-issues the session cookie), `POST /auth/logout`, `POST /auth/logout-all`, `POST /auth/sessions/revoke`, `POST /auth/backchannel-logout` (OIDC Back-Channel Logout 1.0 — the Lab calls it on sign-out and we revoke by `oidc_sid`; it is deliberately exempt from the CSRF Origin guard because it is a server-to-server call authenticated by a signed `logout+jwt`, which is strictly stronger). Client id `integrauth-website`, scope **exactly** `openid email` — keep it equal to the Lab's seeded grant scope or returning users get a consent screen instead of a self-closing popup. No access token is retained and no refresh token is requested: nothing here calls the Lab's API after login, and the ID token already carries `sub` + `email`.
- **Two things that follow from this and surprise people**: (1) being signed in at the Lab does **not** automatically sign you in here — the OP has no `prompt=none` and its `frame-ancestors 'none'` rules out the hidden-iframe trick, so it costs one click (with an existing grant the popup approves itself). (2) The login popup **cannot** `postMessage` its opener: both apps send `Cross-Origin-Opener-Policy: same-origin`, so the browser severs `window.opener` permanently once the popup goes cross-origin, and `popup.closed` misreports `true` immediately. The callback page hands its result back via a **localStorage write** (`acad_auth_event_v1`, a constant duplicated in `auth.ts` and `academy-auth.js` — keep them equal), backed up by a slow `/auth/session` poll.
- **Config**: `LAB_ISSUER` + `OIDC_CLIENT_ID` are non-secret `[vars]` in wrangler.toml. `IA_WEBSITE_OIDC_SECRET` must hold the **same raw value** as the Lab's env var of the same name (the Lab stores only its SHA-256, so it can never be read back or compared). Provision it as **one GitHub Secret — organisation-level, shared to both repos** — and each repo's CI mirrors it into its own Worker on every deploy, so rotating is "change it in one place, redeploy both". **Neither side ever generates it**, and both now REFUSE to: a value either CI invented would be one the other doesn't know, and since a generated Wrangler secret is masked out of the log and unreadable afterwards, nobody could tell the other side what to match. (The Lab's `provision-cf.sh` used to generate one as a last resort; because the Lab's `IA_WEBSITE_REDIRECT_URIS` is committed, that made `websiteClientConfigFromEnv` non-null and seeded a live confidential OIDC client whose secret was unknowable — sign-in then 401s `invalid_client` until someone sets the org secret and redeploys both. It now warns and leaves it unset.) Unset ⇒ `rpConfigFromEnv()` returns null ⇒ `/auth/*` answers 503 `sign_in_unavailable` (rendered as a self-closing HTML page in **both** popup and redirect mode — returning raw JSON left the popup's opener waiting out its full five-minute timeout, since only that page writes the localStorage handshake) and the account-free Academy keeps working.

  Also required and easy to miss: **`ACADEMY_PRIVATE_JWK` now fails CLOSED.** If it is unset, certificate issuance and the JWKS route 500 rather than falling back to anything. The ephemeral-key fallback still exists for local dev but must be asked for via `ALLOW_EPHEMERAL_CERT_KEY=1`, which lives only in `.dev.vars` (gitignored, in `.assetsignore`, never uploaded by `wrangler deploy`) and therefore cannot reach production. The old unconditional fallback failed open in the worst way: it silently signed real certificates with a key that dies with the isolate and published a *different* public key per isolate, leaving every stored JWT unverifiable with no error anywhere. The Lab's `IA_WEBSITE_REDIRECT_URIS` (comma-separated, max 5, **exact string match, no trailing slash**) must list every origin this Worker answers on with `/auth/callback` appended; the two production URIs are committed there already, and this repo's deploy prints the workers.dev line to paste for staging.
- **This repo's own tables**: `profiles` (first/last name + `name_locked_at`), `academy_lesson_progress`, `academy_quiz_progress`, `academy_last_position`, `academy_exam_attempts`, `academy_certificates`, `academy_progress_epoch` (Lab migration 0053) — all accessed through the parameterized helpers in `src/lib/server/store.ts`.
- **The reset epoch — why deleting progress needs its own channel.** The sync merges by UNION (read lessons are set membership, quiz masks are OR-ed), which is what makes it safe for an offline device to reconnect without deleting anything. The cost is that a union cannot express a DELETION, and "Reset track"/"Reset all" are exactly that. Before this, those buttons undid themselves *visibly*: the local marks cleared, the debounced sync fired ~800ms later, the server unioned every id straight back, and the checkmarks reappeared in front of the learner. Deleting server-side alone is **not** sufficient either — any other device holding the old progress re-uploads its stale copy on its next sync and the reset silently un-happens elsewhere. So: `academy_progress_epoch` holds a per-learner counter, bumped by `POST /progress/reset`. Every client stores it (`acad_epoch`) and echoes it on sync; a client whose epoch is behind has its payload **ignored** and is handed canonical post-reset truth plus the new epoch (`applyServerProgress` then REPLACES local state instead of unioning — unioning an empty server set into a full local one would change nothing, which is the whole trap). A *missing* epoch is treated as current, so older cached JS keeps syncing; a *higher-than-server* epoch is treated as stale, so a client cannot opt out of future resets by asserting a big number. `pushResetToServer()` in functions.js cancels the pending debounced sync **first** — that ordering is load-bearing. Known gap, documented rather than fixed: the server's epoch gate is a read-then-write, so a `/progress/sync` that passed the gate can land its union writes *after* a concurrent `/progress/reset` bumped the epoch, leaving that reset permanently partial (needs two devices racing inside one request).
- **API** (`src/lib/server/api.ts`, Hono, base path `/api/academy`): `GET/PUT /profile`, `GET /progress`, `POST /progress/sync`, `POST /progress/reset`, `POST|GET /exam/attempts`, `POST /certificates/issue`, `GET /certificates`, `GET /certificates/:serial/jwt`, plus two unauthenticated routes — `GET /certificates/verify/:serial` (public verification by serial) and `GET /.well-known/jwks.json` (public key for the certificate JWT; the **only** route that sends CORS, because the whole point is that a third party the learner forwarded a JWT to can verify it — a browser verifier cannot fetch it otherwise). Everything else requires the session cookie. Merge semantics are deliberate: read-lessons union (`INSERT OR IGNORE`), quiz masks bitwise-OR per track, last-position last-write-wins by caller timestamp — a stale device can never delete progress. `lastPosition.updatedAt` must be canonical ISO-8601 and not far-future: the merge decides the winner with a **string** comparison, so a merely-`Date.parse`-able value like `"Sat Jan 01 2050"` sorts above every real timestamp and would wedge the saved place forever. Row growth is bounded two ways — daily caps on exam attempts and certificate issuance, and `MAX_STORED_LESSON_ROWS`/`MAX_STORED_TRACK_ROWS` total ceilings on the progress tables, which have no daily cap because a real learner syncs constantly and whose ids the server cannot validate against a curriculum it does not hold. Known accepted gap, documented in the code: **exam scores are client-asserted** (no server-side answer key exists), so the server can only enforce internal consistency — `passed` must equal `score >= 80`, and a question list must be a genuine 50-question sitting (or the single `legacy-local-pass` sentinel). There is still no per-IP rate limiting (needs a DO/KV).
- **Client** (`js/academy-auth.js`, loaded on ALL 11 pages, exposes `window.AcademyAuth`): **makes no cross-origin calls at all** — identity from this site's own `/auth/*`, Academy data from its own `/api/academy/*`. There is **no OTP form and no Turnstile widget on this site any more** (the credentials are collected at the Lab; the `turnstile-site-key` meta tag was removed from all 11 pages). Ships the navbar sign-in/account dropdown (`#acadAuthNav`, identical markup on every page — `#acadAuthSignIn` is a real `<a href="/auth/start?mode=redirect">` so it still works with JS off, upgraded to the popup by JS), a much smaller sign-in overlay (explains the popup, offers a same-window fallback, reports failures), the themed confirm dialog, and academy.html's `#acadAccount` panel. Session state is cached in **`localStorage`** (`acad_auth_session_v1`) — NOT `sessionStorage`, which made every new tab start out logged-out and show the exam sign-in wall to a signed-in learner — and propagates across tabs/windows via `storage` events. `academy-auth-changed` fires **only on a real identity transition** (signed out↔in, or a different account), not on every tab focus as it used to. `isApiAvailable()` probes `/auth/session` so the Academy degrades to its account-free mode on hosts where the Worker isn't serving (i.e. GitHub Pages, pre-cutover) instead of throwing.
- **Local progress is scoped to the account** (`acad_owner` in localStorage holds the owning `userId`). On sign-in with a *different* `userId`, and on sign-out, `acad_read`/`acad_quiz`/`acad_pos`/`acad_pos_at`/`acad_exam`/`acad_epoch` are wiped before any sync runs. This is not tidiness: without it, on a shared machine learner A's progress synced into B's account on B's next login, and A's `acad_exam.passed` survived so B was offered "claim your prior pass" for a score they never earned — one click from a real, publicly verifiable certificate in B's name. If `acad_owner` is absent, existing local progress is treated as claimable (the intended "carry over my anonymous progress" path).

  **The first sync after signing in has TWO entry points, and both must take the claim path** (fixed 2026-07-30, second re-audit). `claimAnonymousProgress()` — adopt the account's epoch, *then* merge — was reachable only from the `academy-auth-changed` listener, i.e. only on an identity *transition* seen while academy.html is open. But `academy-auth.js` loads on all 11 pages, so a learner can sign in from the home-page navbar and then open /academy, where the session is *already* signed in: no transition, no event, listener never runs. The boot path called `scheduleSync()` unconditionally, which posts epoch 0 — and any account that has ever been reset rejects that as stale and answers with post-reset truth, which `applyServerProgress` applies authoritatively, DESTROYING the anonymous progress it was supposed to carry over. Boot now takes the same `hasUnsyncedLocalProgress()` branch the listener does.

  **`academy-auth-changed` carries a `confirmed` flag.** Listeners that RENDER may use the cached session; listeners that WRITE (the sync) must act only on a server-confirmed one, for the same shared-browser reason as above. The boot event is fired with `confirmed:false`.

  **Two things about WHERE and WHEN this runs are load-bearing, and both were wrong until 2026-07-30.** (1) It lives in `reconcileProgressOwner` in **`js/academy-auth.js`**, not in `initAcademy()`. As an `initAcademy()` listener it never ran at all: `academy-auth.js` fires its forced `academy-auth-changed` synchronously while its deferred script executes, whereas `initAcademy()` registers listeners from jQuery's *asynchronously*-resolved ready callback — so the boot event had always already fired (deterministically, not as a race) — and `initAcademy()` no-ops entirely off academy.html, so a sign-in or sign-out from any other page's navbar reconciled nothing. (2) It runs **only on a server-confirmed session**, never on the localStorage cache. On a fresh browser profile the cache reads as signed-out, so reconciling against it wiped a *legitimate* learner's progress — including a passing exam record — on page load. Correspondingly, the first progress sync waits on `AcademyAuth.ready()` (which resolves after `/auth/session` answers, or after the probe says there is no server), because syncing against a cached guess is exactly how the previous learner's work lands in this learner's account.

  Sync ordering has two more guards worth knowing: `acadSyncGeneration` invalidates any response whose request predates a reset (an in-flight sync returning the *pre*-reset epoch was otherwise applied as authoritative, visibly undoing the reset and then flickering), and a **failed** reset now surfaces a toast with a retry instead of silently un-happening on the next union sync. A first sign-in carrying anonymous progress goes through `claimAnonymousProgress()`, which adopts the account's current epoch *before* merging — without that, signing in to an account that had ever been reset destroyed the anonymous progress it was supposed to claim.
- **Deleting an account happens at lab.integrauth.com/account, not here.** This site offers no delete button — it links out. The Lab's `erasure.ts` is the single canonical RTBF path and already cascades to every Academy table (progress, exam attempts, certificates) plus passkeys. **Never reimplement deletion in this repo**; a second path would diverge. Likewise "Sign out everywhere" here means *every device, for the Academy* — it does not reach the Lab (this site holds no credential permitting that, by design). The reverse direction does work, via back-channel logout.
- **Copy that must stay true to this**: `privacy.html` (Academy accounts / shared account / local-vs-server progress / Resend email / certificate verification / deletion sections), `terms.html` §4 + §8 (Academy accounts, exam & certificate acceptable use), the index.html FAQ **and** its FAQPage JSON-LD twin, and academy.html's exam-section subtitle + the per-track "How to use it" lines. If sign-in requirements change, sweep all of those together.

### Boot loader & async CDN CSS (index.html + academy.html, 2026-07-14)

Both pages ship a full-screen boot loader (IntegrAuth-logo shield + pulse ring) that covers first paint through JS init, killing every flash class (unthemed light content, wrong-theme loader, old page lingering on nav). Four cooperating pieces — **keep them in sync**:

1. **Inline `<head>` script** (first thing in head, both pages): reads `localStorage.theme` (try/catch, defaults `cyber`), stamps `data-boot-theme` + `.site-boot` on `<html>` before body parses, sets `window.__siteBootT0`, and arms a 5s failsafe class-removal in case JS never loads
2. **Inline `<head>` critical CSS** (right after the script): styles `.boot-loader`/`.acad-boot-loader` + shield/scan + per-`data-boot-theme` backgrounds WITHOUT needing styles.min.css, and hides all other body children via `html.site-boot body>:not(...) {visibility:hidden!important}` — so nothing can ever paint ahead of the loader
3. **Inline post-`<body>` script**: rewrites `body.className` to the chosen theme's classes synchronously (applyTheme() re-does it at ready) — no unthemed frame even if the loader lifts early
4. **`dismissBootLoader()` in functions.js**: removes `.site-boot` after ≥700ms AND once Bootstrap's stylesheet is in `document.styleSheets` (capped +4s so a dead CDN can't strand the loader); called from the DOM-ready handler (index, gated on `#siteBootLoader`) and the end of `initAcademy()` (academy)

The 3 CDN stylesheets (Google Fonts, Bootstrap, Font Awesome) load **async** on these two pages (`rel="preload" as="style"` + `onload` rel-swap + `<noscript>` fallbacks) so first paint only blocks on same-origin styles.min.css — the loader paints in the right theme within ~100-300ms while the loader hides the un-Bootstrapped layout. Also in functions.js: a delegated click handler raises the loader over the OLD page on same-site cross-page link clicks (browser paint-holding otherwise shows the old page until the new one's first paint), with same-pathname/hash/new-tab/external clicks excluded and a `pageshow` handler dropping a stale loader on bfcache restores. Legal pages (privacy/terms/support/cancellation) have none of this — blocking CSS, no loader.

- `<meta name="acad-build" content="X.X">` in academy.html's `<head>`, AND `academy-version.txt` at repo root — both must match the new version, or the live-update toast (see below) fires spuriously on every visit.

**Minify labs JS**: `npx terser js/academy-labs.js -o js/academy-labs.min.js -c -m`

**Academy live-update toast** (added 2026-07-13): since GitHub Pages is static (no push channel), `initAcademy()` in functions.js polls `academy-version.txt` and compares it to the page's own `<meta name="acad-build">`, light on the server by design: ONLY on tab `visibilitychange`→visible and whenever `showLesson()` crosses into a new track (not on every lesson turn) — no standing interval (a 24h `setInterval` existed briefly, removed 2026-07-27 as unnecessary background polling for a page that's typically closed well before a day passes). On mismatch it shows a dismissible `.acad-update-toast` ("New lessons & fixes are available." + Reload button) — safe because all progress lives in localStorage, so a reload loses nothing. Forgetting to bump `academy-version.txt`/the meta tag on a deploy just means the toast won't fire for that deploy (not harmful); bumping them without a real deploy would falsely prompt everyone to reload, so always bump together with the real `?v=` cache-bust, from the same commit that ships.

> **EASY TO MISS — check this every time**: `academy.html` always loads `styles.min.css` and `functions.min.js`, so ANY commit that bumps either of those `?v=` numbers (not just Academy-labeled work — a CSS animation tweak, a nav fix, anything) is a real deploy from an open Academy tab's point of view. Bump `<meta name="acad-build">` in academy.html AND `academy-version.txt` to the same next number in that same commit, even if the change looks unrelated to Academy content. Skipping this doesn't break anything visibly (the toast just silently fails to fire), which is exactly why it's easy to forget — there's no error to catch it. This bit a real session on 2026-07-27: three commits bumped styles/functions versions for an Academy confirm-dialog fix and all three forgot the acad-build bump until asked directly.

**Sign-in error handling**: `/auth/*` registers its own Hono `onError` that renders the CLOSING PAGE, not JSON — the closing page's inline script is the only thing that writes the `acad_auth_event_v1` localStorage handshake, so any other error response leaves the opener waiting out its full five-minute timeout and then clearing with no message. `/auth/callback` validates `state` BEFORE acting on the provider's `?error=` parameter: `fail()` clears the `SameSite=Lax` transaction cookie, so handling `error` first let any third-party page kill a victim's in-flight login by navigating them to `/auth/callback?error=access_denied`.

**No raw control bytes in source**: CI fails the build on them (`.ts/.js/.json/.html/.css/.yml/.toml`, excluding `*.min.*`). They make a file BINARY to grep and ripgrep, which then skip it in silence — `oidc-rp.ts` once shipped its open-redirect guard with literal NUL/US/DEL bytes instead of `\x` escapes, behaving identically and typechecking cleanly while being invisible to every text search run over the Worker. Use `\x`/`\u` escapes always. (CR is allowed: `js/functions.js` is CRLF.)
